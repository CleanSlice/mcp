# API Setup (App)

> **The API slice generates a type-safe API client** from your backend's Swagger/OpenAPI specification. Using `@hey-api/openapi-ts`, it creates TypeScript services, types, and schemas that stay in sync with your NestJS API.

---

## Overview

The API slice provides **type-safe API integration**:

```
┌──────────────────────────────────────────────────────────────┐
│  API (NestJS)                                                 │
│                                                               │
│  swagger-spec.json  ◄─── npm run swagger:generate (committed) │
│                                                               │
└──────────────────────────────────────────────────────────────┘
                               │
                               │  npm run build:api
                               │  (openapi-ts)
                               ▼
┌──────────────────────────────────────────────────────────────┐
│  APP (Nuxt)                                                   │
│                                                               │
│  slices/setup/api/                                            │
│  ├── data/repositories/api/                                   │
│  │   ├── client.gen.ts      ◄─── Axios client instance        │
│  │   ├── sdk.gen.ts         ◄─── Service classes              │
│  │   ├── types.gen.ts       ◄─── TypeScript interfaces        │
│  │   └── schemas.gen.ts     ◄─── JSON schemas                 │
│  └── utils/                                                   │
│       └── handleApiAuthentication.ts                          │
│                                                               │
└──────────────────────────────────────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│  FEATURE SLICES                                               │
│                                                               │
│  import { getUsers, type GetUsersData } from '#api/data';     │
│                                                               │
│  const { data } = await getUsers({ query: { page: 1 } });    │
│                                                               │
└──────────────────────────────────────────────────────────────┘
```

## Critical Rules

### 1. Swagger Spec from Neighboring API Folder

For local development, the OpenAPI spec is read from the API project:

```
project/
├── api/
│   └── swagger-spec.json     # Committed; written by `npm run swagger:generate`
├── app/
│   ├── openapi-ts.config.ts  # Points to ../api/swagger-spec.json
│   └── slices/setup/api/     # Generated SDK output
└── admin/
    └── openapi-ts.config.ts  # Can also point to ../api/swagger-spec.json
```

### 2. Generated Files are Auto-Generated

Never manually edit files in the `data/repositories/api/` folder:

```typescript
// data/repositories/api/sdk.gen.ts
// This file is auto-generated by @hey-api/openapi-ts  <-- DO NOT EDIT

export const login = <ThrowOnError extends boolean = false>(
  options: Options<LoginData, ThrowOnError>
) => (options.client ?? client).post<LoginResponses, unknown, ThrowOnError>({
  url: '/auth/login',
  ...options,
});
```

### 3. Use the `#api` Alias

```typescript
// CORRECT - Use alias
import { getUsers, type UserDto } from '#api/data';

// WRONG - Relative paths
import { getUsers } from '../../../setup/api/data/repositories/api';
```

## Installation

### Install Dependencies

```bash
# Hey-API OpenAPI TypeScript generator (client is bundled)
npm install -D @hey-api/openapi-ts

# Axios (required peer dependency for the bundled Axios client)
npm install axios
```

> **Note:** Starting with `@hey-api/openapi-ts` v0.73.0, the `@hey-api/client-axios` package is bundled directly and no longer needs to be installed separately.

## Complete Configuration Example

### `openapi-ts.config.ts` (Root)

```typescript
// @scope:app
// @layer:config
// @type:openapi-config

import { defineConfig } from '@hey-api/openapi-ts';

export default defineConfig({
  input: '../api/swagger-spec.json',
  output: {
    path: './slices/setup/api/data/repositories/api',
  },
  postProcess: ['prettier'],
  plugins: [
    '@hey-api/typescript',
    '@hey-api/sdk',
    '@hey-api/client-axios',
  ],
});
```

> **Key changes from older versions:**
> - `client` option moved into the `plugins` array (v0.63+)
> - `format`/`lint` in `output` replaced by `postProcess` (v0.93+)
> - `@hey-api/client-axios` is bundled — no separate package needed (v0.73+)
> - SDK generates tree-shakeable functions by default (not classes)

### `slices/setup/api/plugins/api.ts`

```typescript
// @scope:app
// @slice:setup/api
// @layer:plugins
// @type:nuxt-plugin

import { client } from '../data/repositories/api/client.gen';

export default defineNuxtPlugin(() => {
  const { apiUrl } = useRuntimeConfig().public;

  client.setConfig({
    baseURL: apiUrl as string,
  });

  client.instance.interceptors.response.use(
    (response) => response,
    (error) => {
      handleError(error);
      return Promise.reject(error);
    },
  );
});
```

> **Note:** The API base URL is configured via Nuxt's `runtimeConfig`. Set the `NUXT_PUBLIC_API_URL` environment variable to override the default.

### `slices/setup/api/nuxt.config.ts`

```typescript
// @scope:app
// @slice:setup/api
// @layer:config
// @type:nuxt-config

import { fileURLToPath } from 'url';
import { dirname } from 'path';

const currentDir = dirname(fileURLToPath(import.meta.url));

export default defineNuxtConfig({
  alias: {
    '#api': currentDir,
  },
});
```

### `slices/setup/api/utils/handleApiAuthentication.ts`

```typescript
// @scope:app
// @slice:setup/api
// @layer:utils
// @type:utility

import { client } from '../data/repositories/api/client.gen';

/**
 * Handle API authentication
 * @param token - Pass token to authenticate, or leave empty to logout
 */
export const handleApiAuthentication = (token?: string) => {
  if (token) {
    client.instance.defaults.headers.common['Authorization'] = `Bearer ${token}`;
  } else {
    delete client.instance.defaults.headers.common['Authorization'];
  }
};
```

### `slices/setup/api/data/index.ts`

```typescript
export * from './repositories';
```

### `slices/setup/api/data/repositories/index.ts`

```typescript
export * from './api';
```

### `slices/setup/api/index.ts`

```typescript
export * from './data';
```

## Environment Configuration

The API base URL is configured via Nuxt's `runtimeConfig` in `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      apiUrl: 'http://localhost:3333',
    },
  },
});
```

Override at runtime with environment variables:

```bash
# .env
NUXT_PUBLIC_API_URL=http://localhost:3333

# Production
NUXT_PUBLIC_API_URL=https://api.yourapp.com
```

Nuxt automatically maps `NUXT_PUBLIC_API_URL` to `runtimeConfig.public.apiUrl`.

## Usage Examples

### Using Generated SDK Functions

```typescript
// SDK generates tree-shakeable functions (not classes)
import { login, getUsers, type UserDto } from '#api/data';

// Login
const { data } = await login({
  body: {
    email: 'user@example.com',
    password: 'password123',
  },
});

// Get all users
const { data: usersData } = await getUsers({
  query: {
    page: 1,
    perPage: 10,
  },
});
```

### Using in Stores

```typescript
// slices/user/stores/user.ts
import {
  getUsers,
  getUser,
  createUser as createUserApi,
  updateUser as updateUserApi,
  deleteUser as deleteUserApi,
} from '#api/data/repositories/api';
import type {
  CreateUserDto,
  UpdateUserDto,
  GetUsersData,
} from '#api/data/repositories/api';

export const useUserStore = defineStore('user', () => {
  const users = ref([]);
  const isLoading = ref(false);

  async function fetchUsers(filter?: GetUsersData['query']) {
    isLoading.value = true;
    try {
      const { data } = await getUsers({
        query: { page: 1, perPage: 10, ...filter },
      });
      if (data) {
        users.value = data.data;
      }
    } finally {
      isLoading.value = false;
    }
  }

  async function createUser(dto: CreateUserDto) {
    const { data } = await createUserApi({ body: dto });
    if (data) await fetchUsers();
    return data;
  }

  return { users, isLoading, fetchUsers, createUser };
});
```

### Using in Components

```vue
<script setup lang="ts">
const store = useUserStore();
await store.fetchUsers();
</script>

<template>
  <div v-if="store.isLoading">Loading...</div>
  <ul v-else>
    <li v-for="user in store.users" :key="user.id">
      {{ user.name }} - {{ user.email }}
    </li>
  </ul>
</template>
```

### Error Handling

Error handling is configured globally via the API plugin's Axios interceptor. The `handleError` utility catches API errors and shows toast notifications. See [Error Setup](./app-error.md) for details.

## Generated SDK Structure

### SDK Functions

Each API endpoint generates a tree-shakeable function:

```typescript
// Functions are named after the Swagger operationId
import {
  getUsers,     // GET /users
  getUser,      // GET /users/:id
  createUser,   // POST /users
  updateUser,   // PATCH /users/:id
  deleteUser,   // DELETE /users/:id
} from '#api/data';
```

### Type Exports

```typescript
import type {
  // DTOs (Data Transfer Objects)
  CreateUserDto,
  UpdateUserDto,

  // Response types
  GetUsersResponses,
  GetUserResponse,
  CreateUserResponse,

  // Request parameter types
  GetUsersData,
  GetUserData,
  CreateUserData,

  // Client options
  ClientOptions,
} from '#api/data';
```

### Client Instance

```typescript
// Import the client for direct configuration
import { client } from '#api/data/repositories/api/client.gen';

// Access the underlying Axios instance
client.instance.interceptors.request.use(...);
client.setConfig({ baseURL: '...' });
```

## Regenerating the SDK

### When to Regenerate

Run `npm run build:api` when:

- Backend API endpoints change
- DTOs are added or modified
- New controllers are added
- Swagger decorators are updated

In every one of those cases the spec has to be refreshed **first** - it is not
rewritten when the API boots:

```bash
cd api && npm run swagger:generate   # refresh the committed spec
cd app && npm run build:api          # refresh the SDK from it
```

Commit both. `build:api` runs inside `dev` and `build`, so a committed SDK that
lags the committed spec means starting the frontend leaves a modified tracked
file in `git status`.

### Development Workflow

```bash
# Terminal 1: Run API (serves /api; writes nothing)
cd api
npm run start:dev

# Terminal 2: Run App (regenerates SDK, then starts Nuxt)
cd app
npm run dev
```

### CI/CD Considerations

For CI/CD, you may want to fetch the spec from a URL:

```typescript
// openapi-ts.config.ts
export default defineConfig({
  input: process.env.SWAGGER_URL || '../api/swagger-spec.json',
  // ...
});
```

## Checklist

### Initial Setup

- [ ] Install `@hey-api/openapi-ts` (dev) and `axios`
- [ ] Create `openapi-ts.config.ts` in app root
- [ ] Create `slices/setup/api/` folder structure
- [ ] Create `plugins/api.ts` with `useRuntimeConfig()` for base URL
- [ ] Create `nuxt.config.ts` with `#api` alias
- [ ] Add `build:api` script to `package.json`
- [ ] Set `NUXT_PUBLIC_API_URL` in `.env` or `runtimeConfig`

### After API Changes

- [ ] Run `npm run build:api` to regenerate SDK
- [ ] Check for TypeScript errors from breaking changes
- [ ] Update component/store code if needed

### Never Do

- [ ] NO manual edits to `*.gen.ts` files
- [ ] NO hardcoding API URLs (use environment variables)
- [ ] NO importing from `./data/repositories/api` directly (use `#api/data`)
- [ ] NO committing generated files without regenerating after API changes
